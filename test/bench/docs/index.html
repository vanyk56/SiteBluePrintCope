Docs/Events/Webhooks

Receiving webhooks

Webhooks push events to your server as they happen, so you never have to poll the API for changes.

ℹ️
Test mode

Events created with test keys are delivered only to endpoints registered in test mode.

Register an endpoint

An endpoint is an HTTPS URL on your server that accepts POST requests with a JSON body. Register it in the dashboard or with the API:

curl https://api.flux.dev/v1/webhook_endpoints \
  -u sk_test_mock_flux_demo_secret_key_000: \
  -d url="https://example.com/hooks/flux" \
  -d "enabled_events[]=invoice.paid" -d "enabled_events[]=invoice.payment_failed" -d "enabled_events[]=customer.subscription.deleted"

The response contains the endpoint id and a signing secret. Store the secret — it is shown only once.

Event types

Subscribe only to the events your integration needs:

  • Billing
    • invoice.paid — an invoice was paid in full
    • invoice.payment_failed — a charge attempt failed
      • retried automatically up to 4 times
      • the customer gets an email after the last attempt
  • Customers
    • customer.created
    • customer.subscription.deleted

Verify signatures

Every request carries a Flux-Signature header: a timestamp and an HMAC-SHA256 of the payload. Compute the HMAC with your endpoint secret and compare in constant time.

import crypto from 'node:crypto';

export function verify(payload, header, secret) {
  const [t, v1] = header.split(',').map((p) => p.split('=')[1]);
  const expected = crypto.createHmac('sha256', secret).update(`${t}.${payload}`).digest('hex');
  // reject replays older than five minutes
  if (Math.abs(Date.now() / 1000 - Number(t)) > 300) return false;
  return crypto.timingSafeEqual(Buffer.from(expected), Buffer.from(v1));
}
⚠️
Use the raw body

Frameworks that parse JSON before your handler change the bytes and break the signature. Read the raw request body.

Retries and ordering

Respond with any 2xx status within 10 seconds. Anything else — or a timeout — schedules a retry:

AttemptDelayNotes
1immediatelyfirst delivery
25 minutesafter a non-2xx response or a timeout
330 minutesthe Flux-Retry header carries the attempt number
42 hours—
58 hourslast attempt, then the event moves to dead letters
  1. Return 200 as soon as the event is stored; process it asynchronously.
  2. Deduplicate by event.id — retries deliver the same id.
  3. Do not rely on ordering: fetch the object if you need its latest state.
Tip: press Shift + R in the dashboard to resend any event to a local tunnel.
