**Ссылка на сайт или захват из браузера → `SITE_CLONE_BLUEPRINT.md` + рабочий проект Next.js 16 + React 19 + Tailwind v4.** В проекте есть мок-API и интерактивные компоненты. После генерации он сам собирается, сам исправляет ошибки сборки и сравнивает себя с оригиналом (`VERIFICATION_REPORT.md`). Блюпринт и проект — материал для ИИ-кодера (Cursor, Claude Code, Codex, Windsurf), который доводит копию до 1:1.

```text
 источник                       захват                                генерация                          самопроверка
 URL ──► CLI-краулер ──────┐    computed DOM + CSS, скриншоты,        токены → Tailwind v4 (@theme),     next build → разбор ошибок →
         (Playwright)      ├──► SVG, шрифты, медиа, тексты,      ──►  секции → TSX, "use client"-   ──►  правила + LLM-патчи (до 4 раз)
 Расширение Chrome ────────┘    SingleFile-снимки, XHR/fetch,         стейт, мок-API route.ts,           next start → pixelmatch →
 (ваш браузер): ZIP или         вкладки / модалки / меню              LLM-разбор → блюпринт              VERIFICATION_REPORT.md
 POST в `listen` :3005
```

Что ещё появилось:

- **Расширение Chrome (MV3).** Захват из вашего собственного браузера: страницы, где вы вошли в аккаунт; страницы, которые открылись после того, как вы сами прошли капчу или проверку Cloudflare; SPA в нужном состоянии. Кнопки «Клонировать страницу» и «Клонировать сайт (с краулингом ссылок)». Результат — ZIP или отправка в `site-blueprint listen`.
- **API-сниффер и мок-API.** Ответы XHR/fetch сайта (REST, GraphQL, HTML-фрагменты) записываются, маскируются и превращаются в `app/api/[...route]/route.ts`. Клону не нужен настоящий бэкенд.
- **Интерактивный стейт.** Бургер-меню, модалки, корзина, аккордеоны, вкладки, фильтр/поиск/сортировка каталога — настоящие `"use client"`-компоненты с `useState`, а не статичная вёрстка.
- **Санитайзер CSS для Tailwind v4 / Lightning CSS.** Длинные `data:`-URI, маски и многослойные градиенты выносятся в переменные `globals.css`. Раньше такие arbitrary-классы ломали сборку.
- **Самовосстанавливающаяся сборка.** `next build` → разбор ошибок (webpack и Turbopack) → детерминированные исправления и минимальные SEARCH/REPLACE-патчи от LLM → повтор.
- **Визуальная регрессия.** `next start` на свободном порту, скриншоты клона, `pixelmatch` против скриншотов оригинала по страницам и секциям. Три честные метрики: «по секциям» (с выравниванием сдвигов), «строгое» (пиксель в пиксель, без выравнивания) и «раскладка» (совпадение положения текстовых блоков). Итог — `VERIFICATION_REPORT.md` с картинками «оригинал | клон | отличия».
- **Точность вёрстки.** Бенчмарк из 8 разных сайтов (`npm run bench`, 28 снимков desktop + mobile): среднее сходство по секциям **99.97 %**, минимум **99.7 %** (до доработки — 90.2 % и 30.3 %), строгое 99.97 %, раскладка 99.9 %. Две фикстуры (журнал и дашборд) добавлены уже после основных исправлений, чтобы проверить, что они общие. Переносятся авторские шаблоны сеток (`264px minmax(0,1fr) 224px`, `repeat(auto-fill, …)`, `grid-template-areas`), float и clearfix, CSS-колонки (`columns`, `column-rule`), счётчики (`counter()`), буквицы (`::first-letter`), `::marker`, `::placeholder`, фон/маски/`background-clip` у псевдоэлементов, `vertical-align`, `text-overflow`, `word-break`, `text-wrap: balance`, `appearance`/`accent-color`, значения `range`/`progress`, модель границ таблиц (`border-collapse: separate`, `border-spacing`, `table-layout: fixed`), нативный вид `progress`/`meter` с `accent-color` (preflight Tailwind иначе включает запасной зелёно-серый). Равные боковые отступы проверяются поведением: `mx-auto` ставится, только если `margin: auto` действительно даёт то же положение, а авторская ширина в px не превращается в `w-full`. Обёртки оригинала (`.container`, колонка приложения рядом с сайдбаром) воссоздаются вокруг секций, разделители `<hr>` между секциями не теряются, повторяющиеся элементы сохраняют порядок относительно соседей.

## Что делает

1. **Краулер (Playwright, Chromium)** обходит сайт по внутренним ссылкам и sitemap до глубины `--depth` и соблюдает `robots.txt`. Если сайт запрещает ИИ-ботов, краулер предупреждает. Он закрывает cookie-баннеры, прокручивает страницу до конца, догружает lazy-картинки (`data-src`, `loading="lazy"`, IntersectionObserver), ждёт шрифты и доигрывает анимации появления. Страницы одного шаблона (`/blog/*`) берутся выборочно (`--per-template`). Трекеры блокируются на уровне сети.
2. **На каждой странице (десктоп 1440px + мобильный 390px) собирается:**
   - полноразмерные скриншоты, кадры каждой секции, скриншоты выпадающих и мобильного меню;
   - **computed CSS** каждого элемента: цвета, шрифты, размеры, отступы, скругления, тени, градиенты, transitions, анимации, авторские media queries;
   - все **SVG** (очищенные, `currentColor`, `<use>` развёрнуты), картинки, фоны, видео, шрифты со всеми подмножествами `unicode-range`. Всё скачивается в `project/public/`, повторы склеиваются по хэшу;
   - все **тексты**, включая скрытые: аккордеоны, каждая вкладка и каждый фильтр, пункты dropdown и бургер-меню, hover-состояния (мышь реально наводится);
   - **модалки и выдвижные панели** (корзина, «подробнее», `role="dialog"`): размер, фон, затемнение, тексты, скриншот;
   - **XHR/fetch-ответы** собственного бэкенда сайта (для мок-API) и список найденных трекеров (для отчёта, в клон не попадают);
   - **SingleFile-снимок** живого DOM (`snapshots/*.html`) и чистый DOM без скриптов (`dom/*.html`).
3. **Анализатор** находит секции (Header, Hero, логотипы, Features, Stats, Pricing, Testimonials, Tabs, FAQ, формы, CTA, блог, команда, каталог, Footer…) и общие блоки между страницами. **Одинаковые карточки сворачиваются в один шаблон + массив данных** (`items.map(...)`). Дизайн-токены (палитра с ролями, типографика, отступы, контейнеры, радиусы, тени) переводятся в **Tailwind v4**: `@theme` и классы с `md:` / `lg:`.
4. **Генератор** пишет `project/`: Next.js 16 + React 19 + Tailwind v4, layout, страницы, секции, иконки (`components/icons.tsx`), интерактивные компоненты, мок-API, `next.config.mjs` с rewrites на моки.
5. **LLM** (по умолчанию **GLM-5.3-Flash** через Z.ai; подойдёт любая модель с OpenAI-совместимым API) смотрит на скриншоты и данные. Она дописывает дизайн-язык, визуальные правки компонентов, порядок сборки и риски, а при сборке чинит ошибки. Без ключа инструмент тоже работает: блюпринт детерминированный, сборка исправляется только правилами.
6. **Самопроверка** (включена по умолчанию): сборка с самоисправлением, затем визуальная регрессия → `VERIFICATION_REPORT.md`.
7. **`SITE_CLONE_BLUEPRINT.md`** — главный документ:
   - **§0 мастер-промпт** для ИИ-кодера · §1 обзор страниц (robots, ИИ-боты, удалённые трекеры) · **§2 дизайн-токены** и готовый `app/globals.css`;
   - **§3 ассеты** (SVG как TSX, картинки, шрифты, favicon/OG) · **§4 контент 1:1** · **§5 архитектура** · **§6 компоненты** (факты DOM/CSS, скриншот, разбор LLM, готовый TSX);
   - **§7 скрытый контент и интерактив** (что уже работает в `project/`, таблица мок-API, hover-состояния) · §8 адаптив и анимации · §9 QA-чеклист.
8. **Архив `<папка>.zip`** — всё для ИИ-кодера одним файлом, без сырых данных.

## Установка

Нужен **Node.js 20.12+**. Рекомендуется 22.13+: на нём проходят все юнит-тесты.

```bash
npm install
npx playwright install chromium      # или: npm run setup
cp .env.example .env                  # и впиши LLM_API_KEY (можно без ключа: --no-llm)
```

Ключ Z.ai: z.ai → API Keys. Для GLM Coding Plan поставь `LLM_PROVIDER=zai-coding`. Вместо скачанного Chromium можно взять свой браузер: `--browser-path` / `BROWSER_PATH` или `--channel chrome|msedge`.

## Запуск

```bash
node bin/site-blueprint.mjs https://example.com --depth 2      # обойти сайт и собрать всё
npm start                                                       # спросит ссылку
node bin/site-blueprint.mjs example.com -d 1 -p 5 --no-llm      # быстро и без нейросети
node bin/site-blueprint.mjs --from output/example.com-20250101-1200 --provider gemini --model gemini-2.5-flash   # пересобрать без обхода

node bin/site-blueprint.mjs listen --port 3005                  # приёмник для расширения
node bin/site-blueprint.mjs import ~/Downloads/site-blueprint/example.com-20250101-1200-page.zip

node bin/site-blueprint.mjs heal output/example.com-20250101-1200            # пересобрать project/ и исправить ошибки
node bin/site-blueprint.mjs verify output/example.com-20250101-1200 --url http://localhost:3000
node bin/site-blueprint.mjs pick output/example.com-20250101-1200 pricing    # вывести TSX отдельной секции (hero, pricing, header…)
node bin/site-blueprint.mjs mcp                                              # запустить MCP-сервер (stdio) для Cursor / Claude Code

# На Windows также доступны нативные лаунчеры:
.\site-blueprint.exe                                            # графический лаунчер (GUI)
.\sb.exe                                                        # интерактивный консольный мастер (TUI)
.\sb.exe https://cursor.com 1 2                                 # быстрый запуск: глубина 1, макс. 2 страницы
```

### MCP-сервер для Cursor / Claude Code / Windsurf

Добавь `site-blueprint` в `.cursor/mcp.json` или `claude_desktop_config.json`, чтобы ИИ-агент мог сам клонировать сайты, вытаскивать дизайн-токены и отдельные секции прямо из чата:

```json
{
  "mcpServers": {
    "site-blueprint": {
      "command": "node",
      "args": ["C:/path/to/site-blueprint/bin/site-blueprint.mjs", "mcp"]
    }
  }
}
```

Доступные MCP-инструменты: `clone_site`, `extract_design_tokens`, `pick_component`, `heal_project`, `verify_clone`.

Результат появится в `output/<домен>-<дата-время>/`. Ответы LLM кэшируются в `data/llm/`: повторный запуск с теми же данными и моделью не тратит токены.

**Как использовать результат.** Открой папку в Cursor / Claude Code / Codex или отправь агенту `<папка>.zip`. Дай мастер-промпт из §0 и `SITE_CLONE_BLUEPRINT.md`, приложи `VERIFICATION_REPORT.md`. Агент начинает с `project/` (`npm install && npm run dev`) и доводит секции с наименьшим сходством. Затем запусти `heal` и `verify` снова.

## Браузерное расширение

Папка [`extension/`](extension/) — расширение Chrome (Manifest V3, без удалённого кода). Подробная инструкция — в [extension/README.md](extension/README.md).

1. `chrome://extensions` → «Режим разработчика» → «Загрузить распакованное расширение» → папка `extension/`.
2. Открой нужную страницу в своём браузере. Если нужно, войди в аккаунт или пройди проверку.
3. В тёмном попапе выбери «Клонировать страницу» или «Клонировать сайт (с краулингом ссылок)» и отметь опции: «Захватить API-запросы», «Захватить интерактивный стейт».
4. Выбери доставку:
   - «Скачать ZIP» — файл `Downloads/site-blueprint/<host>-<дата>-<время>-<page|site>.zip`, потом `site-blueprint import <zip>`;
   - «Отправить в локальный CLI (localhost:3005)» — при запущенном `site-blueprint listen` захват сразу уходит в обычный конвейер. Если CLI недоступен, расширение предлагает ZIP.

Что делает расширение: `content.js` сериализует живой DOM со спрайтами, шрифтами и медиа, прокручивает страницу для lazy-load и прогоняет пробы вкладок, аккордеонов, меню и модалок. `inject/api-hook.js` записывает fetch/XHR вкладки. `background.js` склеивает скриншоты, собирает API-ответы в JSON и упаковывает всё в ZIP (формат v1) или отправляет POST в CLI. Токены и персональные данные маскируются уже в расширении, а затем ещё раз в CLI.

**Безопасность `listen`.** Сервер слушает только `127.0.0.1`, проверяет `Host` (защита от DNS rebinding) и отклоняет запросы с Origin обычных сайтов. Нужен служебный заголовок `X-SB-Client`, из-за которого браузер шлёт CORS-preflight, а веб-страницы его не проходят. Можно задать общий токен (`--token` / `SB_LISTEN_TOKEN`). Размер загрузки ограничен (`--max-upload-mb`, по умолчанию 300). Задачи выполняются по одной.

## Мок-API

- **Что пишется.** Ответы fetch/XHR собственного бэкенда сайта: JSON, GraphQL (запросы различаются по `operationName`), HTML-фрагменты, XML. Шум отбрасывается: трекеры и аналитика, статика, эндпоинты Cloudflare/капчи, HMR, RSC-пейлоады. Cache-busters (`?_=1730…`, `?t=`, `?cb=`) не попадают в ключ.
- **Маскирование (по умолчанию).** Заголовки `Authorization`/`Cookie` не сохраняются. JWT, Bearer-токены, ключи и секретные поля становятся `[REDACTED…]`. Email, телефоны и имена заменяются стабильными фейками (`user1@example.com`, `+1 555 010-01-00`, `User 1`), номера карт (с проверкой Луна) — `[REDACTED_CARD]`. Отчёт о заменах есть в `data/api-mocks/index.json` и в §7 блюпринта. `--no-redact` используй только для своих тестовых данных.
- **Как работает в клоне.** `app/api/[...route]/route.ts` ищет мок в `mocks/registry.ts`. Эндпоинты оригинала вне `/api` (например, `/graphql`) перенаправляются через `rewrites` в `next.config.mjs`, внешние хосты — через `/api/__mock/ext/<host>/…`. Если мок не найден, ответ — `404` с подсказкой. Моки подключены статическими импортами, поэтому работают на любом хостинге, включая Vercel.
- Флаги: `--no-api` — без сниффера и мок-API, `--max-mocks <n>` — лимит (250).

## Интерактивность

Пробы во время обхода находят вкладки, фильтры, аккордеоны, бургер-меню, модалки и корзину. Генератор превращает их в рабочие клиентские компоненты:

- бургер → `<MobileMenu>` (состояние `isOpen`, блокировка прокрутки, Esc);
- триггеры диалогов → `<ModalTrigger>` / `<Modal>`; корзина → `<CartProvider>`, `<CartButton>`, `<AddToCart>` (дровер, состояние в `localStorage`, без оплаты);
- `aria-expanded` и аккордеоны → `<Disclosure>`;
- секции с вкладками становятся `'use client'` с `useState`, а панели показывают тексты, снятые пробами;
- сетки товаров получают фильтр по категориям на `useState` (`lib/catalog.ts` → `filterCatalog`). Панель поиска и сортировки по цене — опция `--catalog-tools`: по умолчанию её нет, потому что на оригинале её тоже нет и она сдвигала вёрстку.

## Самопроверка: сборка, исправления, визуальная регрессия

Запускается сразу после генерации (отключить: `--no-verify`).

1. **Зависимости.** По умолчанию (`--deps shared`) ставится один общий `node_modules` рядом с результатами (`output/`) и переиспользуется всеми запусками. `--deps local` ставит в `project/`, `--deps skip` не ставит ничего.
2. **`next build` с самоисправлением** (до `--heal-iterations`, по умолчанию 4). Ошибки webpack и Turbopack разбираются по файлам и строкам. Сначала применяются детерминированные исправления: нет `'use client'`, кастомные элементы в JSX, отсутствующие экспорты и импорты иконок, недопустимая вложенность DOM, CSS, который отвергает Lightning CSS. Остальное уходит в LLM вместе с точной ошибкой и файлом, а ответ применяется как минимальные SEARCH/REPLACE-патчи. Перед изменением файл копируется в `verify/heal-backup/<итерация>/`. Если итерация ничего не изменила, цикл останавливается.
3. **Визуальная регрессия** (отключить: `--no-visual`). Собранный клон запускается через `next start` на свободном порту, снимается в тех же вьюпортах и сравнивается `pixelmatch` (`--threshold`, по умолчанию 0.1) по страницам и полосам секций. Сходство ниже `--min-similarity` (0.85) отмечается в отчёте. Процессы останавливаются вместе со всем деревом на любой ОС.
   - Перед снимками оригинала и клона страница «раскрывается» одинаково: прокрутка до конца, анимации появления (reveal-on-scroll, `opacity: 0` + `transform`) доводятся до конечного состояния, CSS-анимации и переходы замораживаются, видео и карусели останавливаются. Так сравниваются одинаковые состояния, а не случайные кадры анимации.
   - **По секциям** — главная метрика: каждая полоса секции сравнивается с наилучшим вертикальным сдвигом (поиск в пределах разницы высот страниц + 48 px, но не больше 1000 px; внутри секции сдвиг может меняться лишь плавно — на ≈8 % высоты 600-пиксельной полосы), поэтому одна лишняя строка сверху не обнуляет всё, что ниже. Разница высот при этом всё равно штрафуется. Участки с живым содержимым (видео, canvas, iframe) маскируются и в счёт не идут.
   - **Строгое** — пиксель в пиксель без выравнивания: показывает реальные сдвиги.
   - **Раскладка** — пересечение (IoU) прямоугольников текстовых блоков оригинала и клона с учётом сдвига полосы: ловит «текст не на своём месте», даже если цвета совпали.
4. **`VERIFICATION_REPORT.md`** — сборка, сходство страниц и худших секций со ссылками на compare/diff, проверка внутренних ссылок клона, следующие шаги.

`--strict` возвращает код выхода 3, если сборка не прошла или сходство ниже порога (удобно для CI). После ручных правок: `site-blueprint heal <папка>`.

## Кроссплатформенность

Windows, macOS, Linux. Пути собираются только через `node:path` и `fileURLToPath`. Имена файлов безопасны для Windows (без `CON`/`PRN`, точек в конце, длина ≤ 60). Внешние команды запускаются без shell; исключение — `npm.cmd` на Windows. Дерево процессов `next start` останавливается через группу процессов (POSIX) или `taskkill /T` (Windows). ZIP-архивы пишутся с UTF-8 именами и `/`-разделителями.

## Ограничения

- Canvas/WebGL, сложные JS-анимации и видео-фоны переносятся снимками, скриншотами и ассетами, а не кодом.
- Сайты с жёсткой анти-бот защитой, капчей или логином CLI-краулер не обходит, и это намеренно. Такие страницы снимает расширение в вашем браузере после того, как вы сами вошли или прошли проверку.
- Мок-API воспроизводит только запросы, которые реально прошли при обходе. Запись (POST/PUT) отвечает записанным ответом и ничего не сохраняет.
- Расширение: нет мобильного прохода, чисто CSS-шный `:hover` не воспроизводится, для скриншотов вкладка должна быть активной, высота скриншота ограничена 16000px. Подробнее — в [extension/README.md](extension/README.md).
- Вёрстка снимается в двух вьюпортах (десктоп 1440 и мобильный 390). Между ними (планшет) брейкпоинты восстанавливаются по медиа-запросам сайта, но промежуточные раскладки, которых не было ни в одном снимке (например, 2 колонки только на 761–1100 px), могут отличаться.
- Позиции, вычисленные из JS (`transform: translate(-50%)` в пикселях, высоты от скриптов), переносятся как значения для снятого вьюпорта.
- Высокое сходство на бенчмарке не гарантирует того же на любом сайте: canvas-графика, сторонние виджеты, A/B-варианты и контент за логином сравнивать не с чем. Смотри `VERIFICATION_REPORT.md` — там худшие секции с картинками «оригинал | клон | отличия».
- Очень большие страницы усекаются (`--max-nodes`). Если блюпринт превышает ~450 тыс. символов, он сокращается, а код уходит в `pages/*.md`.

## Законность, этика и приватность

- Клонируй **только свои сайты** или сайты, на копирование которых у тебя **есть разрешение** (редизайн, миграция, аудит дизайн-системы, внутренний прототип). Тексты, изображения, логотипы и шрифты защищены авторским правом и товарными знаками — не публикуй чужой контент и бренд.
- **Никакого обхода защит.** Инструмент не подделывает и не ротирует User-Agent, не скрывает автоматизацию, не решает капчи и не обходит Cloudflare. По умолчанию соблюдаются `robots.txt` и `crawl-delay`, между страницами есть пауза. Загрузка ассетов при 429/503 замедляется и учитывает `Retry-After`, а страницы с ошибкой (в том числе 429) пропускаются без повторных попыток. Если сайт запрещает ИИ-ботов (GPTBot, ClaudeBot, Google-Extended…), это видно в логе и в §1 блюпринта — такой сайт копируй только с согласия владельца.
- **Защищённые страницы и страницы за логином** снимай только расширением в своём браузере и только там, где у тебя есть доступ и право копирования. Расширение сохраняет то, что ты видишь. Захваченные данные попадают только на твой диск или в `127.0.0.1`; к самому сайту расширение обращается лишь за его ресурсами (картинки, шрифты, CSS, robots.txt).
- **Приватность.** Cookies и заголовки авторизации не сохраняются. Токены, ключи и персональные данные в API-моках маскируются по умолчанию — дважды для захватов расширением. Трекеры и аналитика блокируются при обходе и вырезаются из `snapshots/`, `dom/` и `project/`. В блюпринт попадает только отчёт о том, что было удалено.
