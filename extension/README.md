# site-blueprint — расширение для Chrome (Manifest V3)

Захватывает **живую страницу в твоём собственном браузере**: после выполнения JavaScript, со всеми стилями, шрифтами, ленивыми картинками, ответами API и интерактивными состояниями. Захват уходит в `site-blueprint` CLI (ZIP-файлом или напрямую на `localhost:3005`), и CLI строит из него тот же результат, что и после обычного обхода: `SITE_CLONE_BLUEPRINT.md`, проект Next.js 16 + Tailwind v4 с мок-API, снимки и отчёт самопроверки.

Расширение нужно там, где CLI-краулер бессилен или неуместен:

- страницы **за логином** (личный кабинет, админка твоего сервиса) — ты входишь сам, расширение сохраняет то, что ты видишь;
- сайты, которые показывают проверку «вы человек?» (Cloudflare, капча) — **ты проходишь её сам**, расширение ничего не обходит;
- SPA, у которых нужное состояние появляется только после действий пользователя (открытый фильтр, выбранная вкладка, введённый поиск).

## Установка (режим разработчика)

1. Скачай/распакуй `site-blueprint` и (один раз) установи зависимости CLI: `npm install`.
2. Открой `chrome://extensions` (Edge: `edge://extensions`, Brave/Opera/Vivaldi — аналогично).
3. Включи **«Режим разработчика»** (переключатель справа вверху).
4. Нажми **«Загрузить распакованное расширение»** и выбери папку `extension/` из репозитория.
5. Закрепи значок site-blueprint на панели (иконка-пазл → булавка).

Нужен Chrome / Chromium 116+. Обновление после `git pull`: кнопка ↻ на карточке расширения в `chrome://extensions`.

## Как пользоваться

1. Открой страницу, которую нужно клонировать (если нужно — войди в аккаунт, закрой баннеры, выбери нужное состояние).
2. Нажми на значок расширения. В тёмном окне:
   - **«Клонировать страницу»** — текущая вкладка;
   - **«Клонировать сайт (с краулингом ссылок)»** — текущая страница + страницы того же сайта по ссылкам (макс. страниц, глубина, учёт `robots.txt`; одинаковые шаблоны вроде `/blog/*` берутся выборочно).
3. Опции:
   - **«Захватить API-запросы»** — ответы XHR/fetch этой вкладки (JSON, GraphQL, HTML-фрагменты) → мок-API клона;
   - **«Захватить интерактивный стейт»** — вкладки и фильтры каталога, аккордеоны, `<details>`, выпадающие меню, модалки и выдвижные панели (кликает только по безопасным элементам и не уходит со страницы);
   - доставка: **«Скачать ZIP»** или **«Отправить в локальный CLI (localhost:3005)»**.
4. Во время захвата вкладка прокручивается (так догружаются lazy-картинки и бесконечные списки) — **не переключай вкладку, пока идёт скриншот**: Chrome снимает только видимую вкладку. Окно расширения можно закрыть — работа продолжается в фоне, прогресс виден при повторном открытии; есть кнопка «Отменить».

### Доставка: ZIP

ZIP сохраняется через загрузки браузера в подпапку `site-blueprint/` (`<домен>-<дата>-<время>-page.zip` или `…-site.zip`); готовая команда для импорта показывается в окне расширения. Дальше:

```bash
node bin/site-blueprint.mjs import ~/Downloads/site-blueprint/example.com-20250101-1200-page.zip
# Windows: node bin\site-blueprint.mjs import "%USERPROFILE%\Downloads\site-blueprint\example.com-20250101-1200-page.zip"
# флаги те же, что у обычного запуска: --no-llm, --provider gemini, --no-verify, --offline …
```

### Доставка: локальный CLI

```bash
node bin/site-blueprint.mjs listen --port 3005          # npm run listen
node bin/site-blueprint.mjs listen --port 3005 --token my-secret --no-verify
```

Индикатор в шапке окна показывает, запущен ли CLI. Захват отправляется `POST http://127.0.0.1:3005/capture`, CLI ставит его в очередь (по одному), импортирует и запускает весь конвейер; в окне видны этапы и путь к результату. Если CLI недоступен, расширение само сохранит ZIP. Порт и токен меняются в «Настройках» окна расширения (должны совпадать с `--port` / `--token`).

## Что захватывается

| Данные | Как |
| --- | --- |
| DOM со стилями | тот же экстрактор, что у CLI (`src/inpage/extract.mjs` → `lib/inpage.js`): computed styles каждого элемента, токены, секции, тексты, ссылки |
| Автономный HTML-снимок | как SingleFile: живой DOM после JS, CSSOM (в т.ч. `adoptedStyleSheets`), `::before/::after`, Shadow DOM (и закрытый — через хук `attachShadow` в `document_start`), same-origin iframe, кадр canvas/WebGL, состояние форм; скрипты удаляются |
| Ленивая загрузка | `loading=lazy`/`data-src` → eager, пошаговая прокрутка (IntersectionObserver, бесконечные ленты), ожидание шрифтов и картинок, доигрывание анимаций появления |
| SVG-спрайты | `<use href="sprite.svg#id">` разворачиваются инлайн (после захвата страница восстанавливается) |
| Шрифты, картинки, медиа, иконки | скачиваются из кеша браузера; CSS с чужих CDN, которые страница не может прочитать, — фоновым скриптом |
| Скриншот всей страницы | прокрутка + `captureVisibleTab` + склейка (до 14 экранов / 16 000 px); фиксированные шапки и cookie-баннеры скрываются на повторных кадрах |
| API | обёртка `fetch`/`XMLHttpRequest` в MAIN world с `document_start` (ответы, которые страница получает после загрузки расширения) + повтор GET-запросов, сделанных до неё (Resource Timing); с разрешением на сайт — перезагрузка вкладки для полного захвата с первого запроса |
| Трекеры | список скриптов и инлайн-сниппетов → отчёт в блюпринте (GTM, GA, Метрика, Pixel…); в клон они не попадают |
| Гидрация | `__NEXT_DATA__`, `__NUXT__`, Apollo/Redux state, JSON-LD — для данных и подсказок в блюпринте |

Формат архива описан в [`lib/package.js`](lib/package.js) (`site-blueprint-capture`, версия 1); его читает `src/capture/import.mjs`.

## Разрешения и зачем они нужны

| Разрешение | Зачем |
| --- | --- |
| `activeTab` | доступ к вкладке **только после твоего клика** по значку; без постоянного доступа к сайтам |
| `scripting` | внедрить скрипт захвата во вкладку (только по нажатию кнопки) |
| `downloads` | сохранить ZIP |
| `webRequest` | только наблюдение: какие запросы ещё не завершились (ожидание «тишины» сети), метаданные XHR/fetch; ничего не блокирует и не меняет |
| `storage` | настройки окна (опции, порт, токен) |
| `http://127.0.0.1/*`, `http://localhost/*` | связь с локальным `site-blueprint listen` |
| `<all_urls>` (**необязательное**, запрашивается отдельно) | нужно только для «Клонировать сайт» (открывать другие страницы сайта), для ассетов с CDN (галочка «Ассеты с CDN») и для полного захвата API с перезагрузкой. Отозвать: «Настройки» → «Отозвать доступ к сайтам» |

Расширение не читает cookies, не трогает другие вкладки, не отправляет данные никуда, кроме твоего `127.0.0.1`, не загружает удалённый код и не содержит аналитики.

## Приватность

- Секретные заголовки (`Authorization`, `Cookie`, `X-API-Key`, CSRF…) не записываются уже в странице.
- Ответы API проходят **редакцию** дважды (в расширении и в CLI): токены, пароли, JWT, ключи API, номера карт → `[REDACTED]`; e-mail, телефоны, имена, адреса → стабильные фейки (`user1@example.com`, `+1 555 010-01-00`, `User 1`). Отключить можно только в CLI (`--no-redact`) — и только для своих тестовых данных.
- В захват попадает то, что видно на странице. **Перед захватом личного кабинета** убедись, что на экране нет чужих персональных данных; результат не публикуй.

## Ограничения

- **Нет мобильного прохода**: захват делается в текущем размере окна (CLI-краулер снимает ещё и 390 px). Нужна мобильная версия — сузь окно / включи эмуляцию устройства в DevTools и захвати ещё раз.
- **Hover**: меню, открывающиеся по JS-событиям (`mouseenter`), раскрываются программно; чисто CSS-`:hover` расширение воспроизвести не может — такие состояния читаются из стилей, без скриншота.
- **Скриншоты требуют активной вкладки**: не переключайся во время захвата; очень длинные страницы обрезаются на 16 000 px.
- **«Клонировать сайт»** требует доступа ко всем сайтам (`<all_urls>`), открывает страницы в отдельном окне того же размера, не заходит в `logout`/`checkout`/`cart`/`wp-admin`, ждёт ≥ 1 с между страницами (или `Crawl-delay`) и по умолчанию соблюдает `robots.txt`.
- Запросы, сделанные страницей до установки перехватчика, без разрешения на сайт восстанавливаются только для GET; тела POST-запросов до захвата недоступны.
- Кросс-доменные iframe (виджеты, видео-плееры) не сериализуются — в снимке остаётся ссылка.
- Поддерживается Chromium (Chrome, Edge, Brave, Opera, Vivaldi, Arc). Firefox/Safari — не тестировались.

## Этика

Клонируй только **свои** сайты или сайты, на копирование которых **у тебя есть разрешение** (редизайн, миграция, аудит дизайн-системы). Расширение не подделывает браузер, не ротирует User-Agent, не решает капчи и не обходит защиту — оно сохраняет то, что ты уже открыл законным образом. Тексты, изображения, логотипы и шрифты принадлежат владельцам.

## Разработка

```text
extension/
  manifest.json      MV3; версия синхронизируется с package.json
  background.js      service worker: оркестрация, webRequest, скриншоты, ассеты, обход сайта, ZIP / POST в CLI
  content.js         MAIN world: window.__sbCapture (prepare, extract, snapshot, probe, shotScroll, fetchAsset…)
  inject/api-hook.js перехват fetch/XHR (document_start, MAIN world)
  popup.html/css/js  тёмное окно расширения
  download.html/js   сохранение больших ZIP (Blob из IndexedDB → chrome.downloads)
  lib/zip.js         ZIP-писатель (store + deflate через CompressionStream)
  lib/package.js     формат захвата v1 (CapturePackager)
  lib/idb.js         IndexedDB-хранилище готовых архивов
  lib/inpage.js      ГЕНЕРИРУЕТСЯ из src/inpage/{extract,snapshot,prepare,probes}.mjs
  lib/hooks.js       ГЕНЕРИРУЕТСЯ из src/inpage/hooks.mjs
  lib/redact.js      ГЕНЕРИРУЕТСЯ из src/capture/redact.mjs
```

После изменений в `src/inpage/*` или `src/capture/redact.mjs`: `npm run build:extension` (проверка без записи — `node scripts/build-extension.mjs --check`, её запускают юнит-тесты).

Тесты: `npm run test:unit` (формат архива, ZIP, сервер `listen`, импорт захвата в Playwright) и `npm run test:extension` — настоящее расширение в Chromium (`--load-extension`, нужен Chromium/Chrome for Testing): клики в popup, доставка в CLI (`--zip` — через загрузку, `--site` — обход сайта), проверка результата.
